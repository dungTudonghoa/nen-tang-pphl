# Problem Model

Status: Learning exercise baseline; domain semantics are intentionally incomplete.

## Purpose

Formulate a neutral constrained multi-resource assignment problem precisely enough that entities, decisions, constraints, objectives, and unresolved semantics can be distinguished before selecting an algorithm.

## Entities

To be defined by the learner during the first domain exercise.

## Inputs

To be defined from accepted problem semantics rather than inferred from implementation convenience.

## Outputs

To be defined after the decision variables and acceptance criteria are understood.

## Decision Variables

Unresolved. The learner must distinguish controllable choices from input facts and derived values.

## Constraints

Unresolved. Hard feasibility rules must be separated from preferences or optimization objectives.

## Objectives

Unresolved. No objective function is selected by the harness bootstrap.

## Assumptions

Only assumptions explicitly accepted by the human owner belong here. None are added by the bootstrap beyond the neutral research framing.

## Unresolved Semantics

- Exact meaning of a geometric conflict.
- Whether endpoint touching counts as a conflict.
- Numeric precision and tolerance requirements.
- Production problem-size limits.
- Runtime and memory budgets.
- Deployment hardware and operating environment.

## Intended Scale

Not yet an authoritative production requirement. Scaling targets must be recorded only after the learner states and the owner accepts them as part of the neutral problem formulation.

## Non-goals

- Selecting a production optimization algorithm before the problem model is understood.
- Treating toolbox behavior as domain authority.
- Encoding hardware-specific assumptions before a deployment target exists.
